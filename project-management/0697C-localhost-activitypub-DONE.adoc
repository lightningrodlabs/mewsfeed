== Abstract

Phase 2 ("Local Protocol I/O") of FediMew builds on the type foundations
delivered in Phase 1 (link:0697B-phase1-DONE.adoc[0697B], now 100% complete).

The goal is to make the `activitypub-s2s` crate at
link:../crates/activitypub-s2s/[`crates/activitypub-s2s/`] serve real
ActivityPub HTTP endpoints on localhost, testable with `curl`, `openssl`,
`jq`, and `socat` via bash scripts -- *without* involving the Holochain DHT.

.Deliverables
* An HTTP server (axum) exposing WebFinger, Actor, Inbox, and Outbox endpoints
* RSA key generation, HTTP Signature signing and verification
* An outbound HTTP client for activity delivery
* A `FederationDataSource` trait abstracting the data layer (mock for Phase 2,
  zome calls for Phase 3)
* Bash test scripts exercising every protocol flow individually
* An example binary (`localhost_server`) for manual exploration

Phase 1 delivered 14 pure data types with serde serialization. Phase 2 adds
networking, crypto, and HTTP handling to make them live on the wire.

.Rationale for key choices
[cols="1,3"]
|===
| axum | Built on tokio/hyper, same runtime as reqwest. Typed extractors produce
  testable handler signatures. Actively maintained by the tokio team.

| reqwest | Already specified in architecture docs (link:fedimew.md[`fedimew.md`]
  line 67). Shares tokio runtime with axum.

| rsa + sha2 + base64 | Pure-Rust RSA. No system OpenSSL or C compilation
  needed. Natively handles PEM encoding for `publicKeyPem` in Actor JSON.
  HTTP Signatures (draft-cavage) use RSA-SHA256: PKCS#1 v1.5 + SHA-256.
|===

No changes to the workspace root `Cargo.toml` are needed -- the `crates/*`
glob already includes `activitypub-s2s`.

=== Module Specifications

==== error.rs

Unified error type using `thiserror`. Implements axum's `IntoResponse` to map
errors to HTTP status codes directly from handler return types.

[source,rust]
----
#[derive(Error, Debug)]
pub enum S2SError {
    BadRequest(String),       // -> 400
    NotFound(String),         // -> 404
    Unauthorized(String),     // -> 401
    Internal(String),         // -> 500
    Crypto(String),           // -> 500
    HttpClient(reqwest::Error),
    Json(serde_json::Error),
    SignatureParse(SignatureParseError),
}
----

==== crypto.rs

RSA key management and HTTP Signature operations. This module has NO dependency
on the HTTP server -- it is pure crypto logic.

.Public API
[source,rust]
----
pub fn generate_rsa_keypair() -> (RsaPrivateKey, RsaPublicKey);
pub fn public_key_to_pem(key: &RsaPublicKey) -> String;
pub fn build_signing_string(
    method: &str, path: &str,
    headers: &[(String, String)],
    signed_headers: &[&str],
) -> String;
pub fn sign(signing_string: &str, private_key: &RsaPrivateKey) -> Result<String, S2SError>;
pub fn verify(
    signing_string: &str, signature_b64: &str, public_key_pem: &str,
) -> Result<bool, S2SError>;
pub fn compute_digest(body: &[u8]) -> String;  // "SHA-256=base64..."
pub fn build_signature_header(
    key_id: &str, signed_headers: &[&str], signature_b64: &str,
) -> String;
----

Inline unit tests: sign/verify roundtrip, wrong-key rejection, digest of known
input, signing string format.

==== mock_data.rs

Defines the `FederationDataSource` trait -- the clean seam between Phase 2
mock data and Phase 3 zome integration.

[source,rust]
----
#[async_trait]
pub trait FederationDataSource: Send + Sync {
    async fn get_actor(&self, username: &str) -> Result<Option<APActor>, S2SError>;
    async fn get_outbox(&self, username: &str) -> Result<OrderedCollection, S2SError>;
    async fn get_webfinger(
        &self, username: &str, domain: &str,
    ) -> Result<Option<WebFingerResponse>, S2SError>;
    async fn process_inbox(
        &self, username: &str, activity: APActivity,
    ) -> Result<(), S2SError>;
    async fn get_signing_key(
        &self, username: &str,
    ) -> Result<Option<rsa::RsaPrivateKey>, S2SError>;
    async fn get_public_key_pem(
        &self, username: &str,
    ) -> Result<Option<String>, S2SError>;
}
----

`MockDataSource` stores 2 users (`alice`, `bob`) with pre-generated RSA
keypairs. `process_inbox` appends received activities to an `Arc<Mutex<Vec<APActivity>>>`
for inspection by test scripts (exposed via a debug endpoint `GET /__debug/inbox/{username}`).

==== handlers.rs

Four axum handler functions, each receiving `FederationDataSource` via `State`:

[cols="1,2,2"]
|===
| Handler | Route | Behavior

| `webfinger_handler`
| `GET /.well-known/webfinger`
| Parse `resource` query param, validate acct URI, return JRD
  (`application/jrd+json`)

| `actor_handler`
| `GET /users/{username}`
| Check `Accept` header for `application/activity+json`, return Actor JSON

| `inbox_handler`
| `POST /users/{username}/inbox`
| Parse `Signature` header, fetch sender's actor, verify HTTP Signature via
  `crypto.rs`, parse body as `APActivity`, call `process_inbox()`, return 202

| `outbox_handler`
| `GET /users/{username}/outbox`
| Return `OrderedCollection` JSON
|===

== FederationDataSource: Phase 2 / Phase 3 Boundary

The trait is the only part that changes between phases:

[cols="1,2,2"]
|===
| Method | Phase 2 (MockDataSource) | Phase 3 (ZomeDataSource)

| `get_actor`
| Hardcoded alice/bob profiles with real RSA public keys
| `activitypub.profile_to_ap_actor(agent)` via AppWebsocket

| `get_webfinger`
| Hardcoded JRD for alice/bob
| `activitypub.get_webfinger_response(username, domain)`

| `process_inbox`
| Append to in-memory Vec (inspectable via debug endpoint)
| `activitypub.process_follow/like/announce/mention`

| `get_signing_key`
| Pre-generated RSA private key from HashMap
| OS keychain or encrypted local storage

| `get_public_key_pem`
| PEM exported from pre-generated keypair
| Stored in zome `FederationConfig`
|===

.What does NOT change in Phase 3
* `server.rs`, `handlers.rs`, `crypto.rs`, `client.rs` -- all remain as-is
* The only new code is `ZomeDataSource` (in a new `conductor.rs` module)
* Holochain types (`ActionHash`, `AgentPubKey`) stay internal to `ZomeDataSource`
* The `federation_types` crate remains a zome-side dependency only

== Bash Test Scripts

All scripts live in `crates/activitypub-s2s/tests/scripts/`. Each script:

* Accepts environment variables: `PORT`, `BASE_URL`, `USERNAME`
* Uses `set -euo pipefail`
* Outputs response headers and body to `output/` directory via `tee`
* Checks HTTP status codes and JSON fields with `jq`
* Exits non-zero on failure

=== lib.sh -- Shared Helpers

[source,bash]
----
#!/usr/bin/env bash
# Shared helpers for ActivityPub protocol test scripts.

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
OUTPUT_DIR="${SCRIPT_DIR}/output"
mkdir -p "$OUTPUT_DIR"

: "${PORT:=3000}"
: "${BASE_URL:=http://localhost:${PORT}}"

# Colors for pass/fail
GREEN='\033[0;32m'
RED='\033[0;31m'
NC='\033[0m'

pass() { echo -e "${GREEN}PASS${NC}: $1"; }
fail() { echo -e "${RED}FAIL${NC}: $1"; exit 1; }

# Assert HTTP status code
assert_status() {
  local actual="$1" expected="$2" label="$3"
  if [[ "$actual" == "$expected" ]]; then
    pass "$label (HTTP $actual)"
  else
    fail "$label: expected HTTP $expected, got HTTP $actual"
  fi
}

# Assert JSON field value using jq
assert_json() {
  local file="$1" expr="$2" expected="$3" label="$4"
  local actual
  actual=$(jq -r "$expr" < "$file")
  if [[ "$actual" == "$expected" ]]; then
    pass "$label"
  else
    fail "$label: expected '$expected', got '$actual'"
  fi
}

# Assert JSON field contains substring
assert_json_contains() {
  local file="$1" expr="$2" substring="$3" label="$4"
  local actual
  actual=$(jq -r "$expr" < "$file")
  if [[ "$actual" == *"$substring"* ]]; then
    pass "$label"
  else
    fail "$label: '$actual' does not contain '$substring'"
  fi
}

# Sign an HTTP request using openssl (for bash-side signature construction)
# Usage: sign_request METHOD PATH BODY KEY_FILE KEY_ID
sign_request() {
  local method="$1" path="$2" body="$3" key_file="$4" key_id="$5"
  local date host digest signing_string signature

  date=$(date -u +"%a, %d %b %Y %H:%M:%S GMT")
  host="localhost:${PORT}"

  # Compute SHA-256 digest of body
  digest="SHA-256=$(echo -n "$body" | openssl dgst -sha256 -binary | base64)"

  # Build signing string
  signing_string="(request-target): $(echo "$method" | tr '[:upper:]' '[:lower:]') ${path}
host: ${host}
date: ${date}
digest: ${digest}"

  # Sign with RSA-SHA256
  signature=$(echo -n "$signing_string" | \
    openssl dgst -sha256 -sign "$key_file" | base64 | tr -d '\n')

  # Output headers for curl
  echo "-H \"Date: ${date}\""
  echo "-H \"Host: ${host}\""
  echo "-H \"Digest: ${digest}\""
  echo "-H \"Signature: keyId=\\\"${key_id}\\\",algorithm=\\\"rsa-sha256\\\",headers=\\\"(request-target) host date digest\\\",signature=\\\"${signature}\\\"\""
}

#!/usr/bin/env bash
set -euo pipefail
source "$(dirname "$0")/lib.sh"

echo "=== Test: Inbox POST with valid signature ==="

# This test requires that the server exports alice's private key
# for signing (or we use bob's key from a second server instance).
# For Phase 2, we test by starting a second server on PORT_B
# and having it send a signed Follow to the first server.

: "${PORT_B:=3001}"
: "${BASE_URL_B:=http://localhost:${PORT_B}}"

# Step 1: Fetch bob's actor from server B to get key info
curl -s -H "Accept: application/activity+json" \
  "${BASE_URL_B}/users/bob" > "$OUTPUT_DIR/actor-bob.json"

# Step 2: The server on PORT_B delivers a Follow to alice on PORT_A.
# This is done via the __debug/deliver endpoint or a curl script
# that computes the signature using openssl.

# For direct bash signing, we need bob's private key exported as PEM.
# The mock server exposes GET /__debug/key/{username} for test purposes.
curl -s "${BASE_URL_B}/__debug/key/bob" > "$OUTPUT_DIR/bob-private-key.pem"

BODY='{"@context":"https://www.w3.org/ns/activitystreams","type":"Follow","id":"http://localhost:'"${PORT_B}"'/activities/follow-1","actor":"http://localhost:'"${PORT_B}"'/users/bob","object":"http://localhost:'"${PORT}"'/users/alice"}'

KEY_ID="http://localhost:${PORT_B}/users/bob#main-key"
DATE=$(date -u +"%a, %d %b %Y %H:%M:%S GMT")
DIGEST="SHA-256=$(echo -n "$BODY" | openssl dgst -sha256 -binary | base64)"
HOST="localhost:${PORT}"
REQUEST_TARGET="post /users/alice/inbox"

SIGNING_STRING="(request-target): ${REQUEST_TARGET}
host: ${HOST}
date: ${DATE}
digest: ${DIGEST}"

SIGNATURE=$(echo -n "$SIGNING_STRING" | \
  openssl dgst -sha256 -sign "$OUTPUT_DIR/bob-private-key.pem" | \
  base64 | tr -d '\n')

STATUS=$(curl -s -o "$OUTPUT_DIR/inbox-signed.json" \
  -w "%{http_code}" \
  -X POST \
  -H "Content-Type: application/activity+json" \
  -H "Date: ${DATE}" \
  -H "Host: ${HOST}" \
  -H "Digest: ${DIGEST}" \
  -H "Signature: keyId=\"${KEY_ID}\",algorithm=\"rsa-sha256\",headers=\"(request-target) host date digest\",signature=\"${SIGNATURE}\"" \
  -d "$BODY" \
  "${BASE_URL}/users/alice/inbox")
assert_status "$STATUS" "202" "Inbox signed Follow -> 202"

# Verify the activity was received via debug endpoint
curl -s "${BASE_URL}/__debug/inbox/alice" > "$OUTPUT_DIR/inbox-alice-received.json"
assert_json "$OUTPUT_DIR/inbox-alice-received.json" '.[0].type' "Follow" \
  "Received activity is a Follow"

#!/usr/bin/env bash
set -euo pipefail
source "$(dirname "$0")/lib.sh"

echo "=== Test: Standalone HTTP Signature sign + verify ==="

# Generate a throwaway RSA keypair with openssl
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
  -out "$OUTPUT_DIR/test-private.pem" 2>/dev/null
openssl rsa -in "$OUTPUT_DIR/test-private.pem" -pubout \
  -out "$OUTPUT_DIR/test-public.pem" 2>/dev/null

# Construct a signing string
BODY='{"type":"Follow","actor":"http://example/users/test"}'
DATE=$(date -u +"%a, %d %b %Y %H:%M:%S GMT")
DIGEST="SHA-256=$(echo -n "$BODY" | openssl dgst -sha256 -binary | base64)"
HOST="example.com"

SIGNING_STRING="(request-target): post /users/bob/inbox
host: ${HOST}
date: ${DATE}
digest: ${DIGEST}"

echo "Signing string:"
echo "$SIGNING_STRING"
echo "---"

# Sign
SIGNATURE=$(echo -n "$SIGNING_STRING" | \
  openssl dgst -sha256 -sign "$OUTPUT_DIR/test-private.pem" | base64 | tr -d '\n')
echo "Signature: $SIGNATURE"

# Verify with correct key
echo -n "$SIGNING_STRING" | \
  openssl dgst -sha256 -verify "$OUTPUT_DIR/test-public.pem" \
  -signature <(echo "$SIGNATURE" | base64 -d) && \
  pass "Signature verified with correct key" || \
  fail "Signature verification failed with correct key"

# Verify with wrong key (should fail)
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 \
  -out "$OUTPUT_DIR/wrong-private.pem" 2>/dev/null
openssl rsa -in "$OUTPUT_DIR/wrong-private.pem" -pubout \
  -out "$OUTPUT_DIR/wrong-public.pem" 2>/dev/null

echo -n "$SIGNING_STRING" | \
  openssl dgst -sha256 -verify "$OUTPUT_DIR/wrong-public.pem" \
  -signature <(echo "$SIGNATURE" | base64 -d) 2>/dev/null && \
  fail "Signature should NOT verify with wrong key" || \
  pass "Signature correctly rejected with wrong key"

echo "=== Signature verify: all tests passed ==="

bash test script access to keys and received activities. They will not exist
in the Phase 3 `ZomeDataSource`.

`ZomeDataSource`:

  AppWebsocket calls to the activitypub zome

  (entry types, link types, validation)
. Wire `ZomeDataSource` into server startup instead of `MockDataSource`
. Test with `curl` against the Holochain conductor
. Test with a local Mastodon instance (Docker) for full interoperability

The HTTP server, handlers, crypto, and client code remain *unchanged* from
Phase 2.
